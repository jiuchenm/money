# 看飞书怎样连接文档、表格和 Agent

更新于 2026 年 7 月 27 日。

> 当前结论：飞书已经完成协同 SaaS 的产品验证，正在验证 AI Agent 第二曲线。文档、多维表格、组织权限和协作入口形成了复合壁垒，AI 增购、续费和稳定执行仍缺少公开证据。

## 飞书已经从协同转向业务执行

| 时间 | 变化 | 战略含义 |
|---|---|---|
| 2024-03 | 团队精简 | 从扩张优先转向商业效率 |
| 2024-06 | 张楠卸任飞书总裁 | 经营和产品进一步集中到谢欣 |
| 2024-09 | 多维表格、低代码集中升级 | 不再只做 IM 和文档，开始承载业务系统 |
| 2025-07 | 知识问答正式发布 | 企业内容可以按原有权限被 AI 检索 |
| 2025 下半年 | 携程、柳工等大客户信号 | 客群从互联网向制造和大型集团扩展 |
| 2026-03 | aily、多维表格 Agent、妙搭集中升级 | Agent 开始生成应用并执行任务 |
| 2026-03 | 飞书 CLI 开放 | 外部 Agent 可以调用消息、文档和日历 |
| 2026-07 | aily 强化团队共享和主动执行 | 从个人助手走向团队 AI 同事 |
| 2026-07 | 上汽宣布集团合作 | 制造业和大型集团继续扩张 |

2024 年的收缩没有结束飞书。它改变了增长方式。飞书开始要求多维表格、行业方案和企业续费承担更多商业结果。

## 复合壁垒怎样形成

飞书的核心组合是：

```
文档知识
× 多维表格业务数据
× 组织权限
× IM、会议和日历
× Agent 执行
```

### 文档保存决策背景

制度、会议、项目记录、评论、引用和版本构成非结构化知识。

### 多维表格保存业务状态

客户、商品、项目、生产、门店和流程被结构化成字段、视图、公式、自动化和仪表盘。

### 协作入口补充实时上下文

IM、会议、妙记和日历记录谁在讨论、决定了什么、下一步由谁负责。

### Agent 在同一权限中工作

aily 和外部 Agent 可以按用户身份访问内容并调用工具。

模型可以被替换。企业已经搭好的表结构、自动化、权限和协作关系很难完整迁移。

## 区分当前产品

| 产品 | 负责什么 | 状态 |
|---|---|---|
| 即时消息 | 人员、群组、通知和机器人入口 | 成熟商用 |
| 云文档 | 文档、表格、演示和协作 | 成熟商用 |
| 视频会议、妙记 | 会议、转写、摘要和待办 | 成熟商用 |
| 知识库 | 组织知识结构和权限 | 成熟商用 |
| 知识问答 | 跨企业内容检索和回答 | 2025 年正式发布 |
| 多维表格 | 数据、视图、自动化和轻量业务系统 | 成熟商用 |
| 多维表格 Agent | 生成表、仪表盘、问卷和自动化 | 2026 年发布 |
| 飞书 aily | 创建连接知识和系统的智能体 | 正式在线，持续升级 |
| 飞书妙搭 | 自然语言生成页面和业务应用 | 已发布 |
| CLI、插件和开放平台 | 让外部 Agent 调用飞书能力 | 已开放 |

“飞书 AI”是多个产品能力的总称，不是一个边界清晰的单独 SKU。

## 字节 AI 生态怎样分工

| 层 | 产品 |
|---|---|
| 基础模型 | 豆包及第三方模型 |
| 云和模型服务 | 火山引擎、火山方舟 |
| 通用 Agent 搭建 | 扣子 |
| 企业身份、数据和执行 | 飞书、aily、多维表格 |

飞书已经接入 DeepSeek、Kimi、MiniMax、智谱和其他模型。它不依赖豆包独占。

飞书与扣子在低代码 Agent 搭建上可能重叠。差别在于飞书更接近企业身份、权限、文档和业务数据。

## 多维表格是最关键的产品

普通文档容易被其他协同套件复制。多维表格位于电子表格、数据库、低代码和协作工具的交叉点。

企业一旦在里面建立：

- 字段和数据口径；
- 公式和自动化；
- 视图和仪表盘；
- 行级权限；
- 跨部门流程；
- Agent 和机器人；

迁移就不再是导出一个 CSV。

多维表格也会制造新风险。业务部门可以快速搭应用，也可能产生重复系统、数据口径冲突和无人维护的影子 IT。

## 商业化数据还不能当财报

📙 谢欣曾预计飞书 2024 年经常性收入超过 3 亿美元。

📙 2026 年媒体称飞书 2025 年营收超过 30 亿元、2026 年第二季度 ARR 同比增长超过 100%。

这些数据属于管理层预期或媒体口径。字节没有提供公开审计财报。ARR 和年度确认收入也不能直接比较。

飞书没有公开当前付费企业总数、AI 增购率、续费率和净收入留存。

官方价格页列出基础版、商业版和企业版。商业版和企业版通常按席位、容量、安全和服务范围报价。AI 功能可能通过套餐、配额、Token 或企业合同收费，没有一张适用于所有客户的统一价格表。

## 客户正在从互联网走向制造业

飞书早期客户集中在互联网、科技和新消费。近两年开始进入汽车、装备制造、连锁零售、酒店和大型集团。

柳工公开案例给出约 1.7 万名员工的覆盖规模。上汽在 2026 年 7 月宣布集团层面合作。

合作公告只能证明部署意愿。它不能证明全员迁移、合同金额和后续续费。

海外 Lark 在东南亚继续扩展零售和实施伙伴。它在欧美仍要面对 Microsoft 365、Google Workspace、Slack 和数据跨境压力。

## 迁移成本来自关系而不是文件

企业迁出飞书要处理：

- 文档链接、评论、版本和知识库结构；
- 群聊、机器人和通知；
- 多维表格字段、公式、自动化和权限；
- 日历、会议、妙记和待办关联；
- SSO、审批和第三方系统；
- Agent 提示、知识索引、工具授权和审计记录。

只使用 IM 的客户容易迁移。把业务系统建在多维表格和 Agent 上的客户很难迁移。

## 当前短板

1. 外部客户关系链弱于企业微信。
2. 政企、教育和中小企业覆盖弱于钉钉。
3. 飞书 AI、知识问答、aily、妙搭和扣子容易让采购者困惑。
4. 大型制造企业需要迁移、集成和实施，会降低纯软件复制速度。
5. Agent 继承权限不能自动解决提示注入、误操作和凭证泄露。
6. Lark 面临数据驻留和字节品牌的地缘政治压力。

## 给当前阶段下定义

飞书处在：

> **协同 SaaS 规模化中期，企业 Agent 第二曲线验证期。**

传统协同已经成立。Agent 能否成为新的高毛利增购层还没有被续费和审计收入证明。
